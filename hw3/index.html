Part 1: Ray Generation and Scene Intersection

Ray Generation and Primitive Intersection Overview

To draw images using ray tracing, a few steps need to be implemented. We need to be able to shoot multiple rays from a camera and through a pixel on the image plane and determine its intersection point on an object in the scene. Afterwards, we can average the values of the resulting intersection points to get the color of the pixel the rays were shot through.

The first step is creating a new ray object, representing by its origin and direction. We are given the normalized image coordinates \(x, y\) in 2D. We can convert the normalized image coordinates to camera space coordinates by transforming it onto the image plane. Normalized image coordinates are in the space \[ \begin{align*} (0, 0)\\ (1, 1) \end{align*} \], and the camera space image plane is in the coordinates \[ \begin{align*} &(-\tan(0.5 \times \text{hFov}), -\tan(0.5 \times \text{vFov}, -1))\\ &(\tan(0.5 \times \text{hFov}), \tan(0.5 \times \text{vFov}), -1) \end{align*} \]. Thus, this transformation is done with the following equations \[ \begin{align*} c_x &= (x - 0.5) * (2.0 * \tan(\text{hFov}) * 0.5)\\ c_y &= (y - 0.5) * (2.0 * \tan(\text{vFov}) * 0.5) \\ c_z &= -1 \end{align*} \]. Afterwards, we can use the given c2w matrix to convert the direction ray from camera space to world space. \[ \text{direction} = \text{c2w} \begin{bmatrix} c_x \\ c_y \\ c_z \end{bmatrix}\]. The origin is simply the pos variable of the camera.

Next, we need to send out ns_aa sample rays for a given pixel \(x, y\) in the normalized image. We can generate a random sample, \(r_x \in [x, x+1], r_y \in [y, y+1]\) using the gridSampler->get_sample() function and adding it to our given pixel. Then, we scale it down to the proper coordinates between \(0, 1\) by dividing it by the buffer width and height. Afterwards, we use our previous function to create rays, camera->generate_ray(), to generate a ray through the random sample and get the global illumination from the ray. After doing this ns_aa times, we take the average and update the sample buffer's pixel.

Finally, we implement detecting intersections. For the triangle intersection, we can use the Möller Trumbore Algorithm, which calculates the triangle Barycentric coordinates and the time \(t\) given the ray and the traingle points. We can use the Barycentric coordinates to both detect the intersection is within the triangle, and to interpolate the normal vectors across the triangles.
For sphere intersection, we can solve for the sphere intersection using the quadratic equation. This gives us two potential times, \(t_1, t_2\). We can then determine the intersection point by calculating the ray position at these times and validate them. We take the smallest valid intersection, and calculate the normals by normalizing the difference between the intersection point and the sphere's origin.
For both intersection methods, we update the ray's max_t to the intersection's t, since it doesn't need to check any intersections past that point.

Triangle Intersection Algorithm

The triangle intersection algorithm I used was the Möller Trumbore Algorithm, which is a simplified equation that solves for a vector \(\begin{bmatrix} t & b_1 & b2 \end{bmatrix}^{\top}\), where \(t\) is the time of intersection and \(b_1, b_2\) are the Barycentric coordinates for the first and second vertices. The general idea for finding the intersection is to determine the ray intersection point with the triangle's plane, then determine if the intersection point is within the triangle's boundaries. Since we are given the Barycentric coordinates of the intersection point, we can easily determine if it is inside the triangle by ensuring that all of the Barycentric coordinates are greater than zero, and their sum is less than one. If this is satisfied, and \(t\) is within the ray's \([r_{\text{min}}, r_{\text{max}}]\), then we have found the intersection between the triangle and the ray. Otherwise, the ray does not hit the triangle.
