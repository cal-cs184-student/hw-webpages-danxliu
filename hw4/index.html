Part 3: Handling collisions with other objects

Implementation

To implement sphere collision, I first determined whether or not the new location of the point mass was inside the sphere's radius or not. If it was outside, then I just returned. Otherwise, I determined the target point by finding the unit vector from the sphere's center to the current point mass location, then multiplying it by the sphere's radius. This is the point that we want the sphere to be at. To get the point mass to the target point, I calculate the correction vector, or the difference between the target point and the last position of the point mass. Finally, I move the location of the point mass by taking its last location and add the correction vector (times 1 - friction) to it and preventing it from intersecting the sphere.

To implement plane collision, I first determine which side of the plane both the current and last positions are. Given the normal vector \(n\) and a point on the plane \(p\), the following equation can be used to determine the side of the plane \(x\) is on based on the negation sign: \[ (x - p) \cdot n \] If both the current and last position are on the same side of the plane, I just return, since no collision occurs. Otherwise, I first calculate the tangent point by projecting the position onto the plane. Then, I calculate the sign, or the direction where the point came from. This can be used to calculate the target point of where we want the point mass to be, which is slightly away from the tangent point in the direction it came from, multiplied by SURFACE_OFFSET. Finally, we again calculate the correction vector by subtracting the last position from the target point, and set the position of the point mass to its last location plus the correction vector times 1 - friction.

Part 4: Handling self-collisions

Implementation

To implement self-collisions, I first implemented a 3D hash function to group together point masses that are in a similar location. This allows us to reduce time in the future when we are checking point masses that are close to each other. To implement the function, I first partitioned the 3D grid into boxes, and determined which box a point belongs to. I reference the points indexes, multiply them each with unique large prime numbers, then add them together to ideally form a unique hash number for each box. Afterwards, I implemented the build_spatial_map function, which loops through the point masses and assigns them to a hash bucket based on their hash value. Finally, I implemented a self_collide function that checks all point masses in the same hash bucket for collisions. For all point masses within a certain distance, \(2.0 * \text{thickness}\), away from the current point mass, I calculate the correction vector. The correction vector is the vector that when applied to the current point mass, moves it \(2.0 * \text{thickness}\) away from the candidate point mass. Finally, I average all of the correction vectors, scale it by simulation_steps, and set the new point mass position to it.

Part 5: Shaders

Shader Programs

Shader programs are snippets of C/C++ style code that run on the GPU to calculate how 3D objects are drawn to the screen. There are two main types of shaders you write: vertex shaders and fragment (pixel) shaders.

The vertex shader is applied to every single vertex. It takes in information about a single vertex, such as its 3D position, normal vector, and texture coordinates. It outputs the final position of that vertex on the screen, along with any other information that should be passed on.

The fragment shader is applied to fragments, pixels from connected triangles formed by the vertices. It takes as input the interpolated data from the step above, such as the interpolated normal or position for the specific pixel, plus global information like camera position or lighting. It outputs the final color of a single pixel on the screen.

Blinn Phong Shading

The Blinn-Phong shading model is a model that creates semi-realistic shading by approximating the different types of lighting. It is made out of three main lighting parts, summed together:

Ambient Lighting: Lighting that lights up the whole model, simulating light bouncing off the walls of a room and creating global illumination.

Diffuse Lighting: Lighting that simulates a diffuse reflection, where light hits a rough surface and bounces evenly in all directions. It causes parts of the object whose normal vectors are pointing directly at the light source to appear brighter, regardless of where the observer is looking from.

Specular Lighting: Lighting that simulates the shiny spots on a surface, like plastic or glass. In the Blinn-Phong model specifically, this is calculated by finding the "halfway vector" between the light source and the observer. If this halfway vector aligns closely with the surface normal, that part of the object appears brighter, creating a specular highlight.

Bump & Displacement Mapping

We can see that there is a slight difference between the bump and displacement mapping. Displacement mapping actually changes the normal vectors of the vertices, acting on both vertices and fragments. On the other hand, bump mapping only changes how the pixels are shaded, acting only on fragments. We can see this in the images, where the displacement mapping cloths are actually deformed along the ridges of the brick lines, whie the bump mapping cloths are still smooth.

Comparing the resolution of the cloth between \(a = 16, o = 16\) and \(a = 128, o = 128\), from first glance there is not much of a difference between the images. However, looking at the displacement mapping we can see that the displacement ridges of the texture look a bit smoother with the higher resolution. The lower resolution causes the cloth to look unnatural and have slightly sharper angles.
